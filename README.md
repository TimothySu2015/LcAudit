# LcAudit — 天堂：經典版 帳號安全稽核工具

帳號被盜之後，最難回答的問題是「**到底是從哪裡被打進來的**」。

LcAudit 在你的 Windows 電腦上蒐集三類跡證，幫你判斷被盜的可能途徑：

1. **你裝的紫P（PURPLE Launcher）是不是官方正版**
2. **這台電腦有沒有被別人遠端連進來過**
3. **有沒有被裝了長期潛伏的後門**

它只看、不動手 —— 全程唯讀，除了報告檔之外不會寫入任何位置，也不會替你清除或修復任何東西。

---

## 這個工具不會做的事

| 不會 | 說明 |
|---|---|
| 不修復、不清除、不隔離 | 只出報告。要不要處理、怎麼處理由你決定 |
| 預設不連網 | 所有檢查全程離線。**只有**在你自己加上 `--email` 並在提示中確認後，才會上傳報告 |
| 不碰遊戲 | 不讀遊戲記憶體、不看封包、不檢查遊戲檔案 —— 這些會踩到反作弊 |
| 不需要安裝 | 單一執行檔，跑完就可以刪掉 |

## 你不必相信我

**「來路不明的執行檔，說要幫我檢查電腦有沒有中毒」—— 你會懷疑是正常的，而且你應該懷疑。**

這個工具會列舉處理程序、讀取安全性事件記錄、查詢防毒設定。這些行為和惡意程式的樣式高度重疊，光靠作者說「我沒有惡意」不構成任何保證。

所以請不要相信我，**去驗證**。依你願意花的力氣，有四層：

| 花多少力氣 | 你能得到的保證 |
|---|---|
| **零** | 把 `LcAudit.exe` 拖到 [VirusTotal](https://www.virustotal.com/) —— 70 多個防毒引擎同時掃描。每個 Release 的說明裡也直接附了掃描連結 |
| **一行指令** | `gh attestation verify` 可證明你手上的 exe **確實是由這份公開原始碼建置出來的**，沒經過任何人的電腦（見下方） |
| **願意讀** | 原始碼全部公開。想確認它沒讀你的記憶體，就去看 —— 而且 CI 有一組測試會在原始碼出現 `ReadProcessMemory`、`CreateRemoteThread` 這類 API 時**直接讓建置失敗**（`ForbiddenApiGuardTests.cs`） |
| **完全不信** | 那就別用我的執行檔。`git clone` 之後自己編，見「[自行建置](#自行建置)」 |

> ### 這一點值得說清楚
>
> 有數位簽章的商業軟體，你能確認的只是「它確實由某家公司發佈」，**你無法確認它做了什麼**。
>
> LcAudit 沒有簽章（原因見下），但它的原始碼是公開的，而且執行檔可以被證明對應到那份原始碼。**這比一張簽章能告訴你的更多。**

### 還是不放心？先用一般權限跑一次

**這個工具不需要系統管理員權限也能跑。** 用一般權限執行，它讀得到的東西極為有限 —— 你可以先這樣跑一次，看它輸出什麼、確認它沒有亂動你的電腦，再決定要不要用管理員身分跑完整版。

```powershell
.\LcAudit.exe          # 不提權，直接跑
```

代價是會少掉約 8 項需要讀取安全性事件記錄的檢查（報告會明確標示哪些沒檢查到，不會假裝通過）。**但先建立信任再給權限，是完全合理的做法。**

### 為什麼沒有數位簽章

不是懶得弄，是兩條路都走不通：

- **Azure Trusted Signing**（微軟的方案，紫P 官方用的就是這個）目前限定**美國／加拿大**、且需**三年以上可查營運歷史**的**組織**，個人開發者的申請在公開預覽期間已暫停。
- **商業憑證**個人可以申請，但一年約 300 美元起，而且一般（OV）憑證簽了照樣會跳 SmartScreen 警告，要累積下載量才會建立信譽。

一個免費工具花這筆錢，換到的只是「警告晚一點消失」。與其如此，不如把力氣放在讓你能**自己驗證**上。

## 開始使用

### 下載

到 [Releases](https://github.com/TimothySu2015/LcAudit/releases) 下載 `LcAudit.exe`。

**不需要安裝 .NET，也不需要安裝任何東西** —— 執行階段已經打包進執行檔裡，下載後直接跑，跑完可以刪掉。

### 先驗證檔案沒被動過手腳

這是一個要在**可能已被入侵的電腦**上執行的安全工具，本身就是攻擊者眼中的高價值目標。請先確認你下載的是原版：

```powershell
Get-FileHash .\LcAudit.exe -Algorithm SHA256
```

把結果對照 Release 頁面上公布的雜湊值。若安裝了 [GitHub CLI](https://cli.github.com/)，也可以直接驗證建置來源：

```powershell
gh attestation verify .\LcAudit.exe --repo TimothySu2015/LcAudit
```

這行指令回報成功，代表你手上這個檔案**確實是由這個 GitHub 專案的原始碼、透過 GitHub 的建置流程產生的** —— 中間沒有經過任何人的電腦，包括我的。

每個 Release 的說明裡也附有 **VirusTotal 掃描連結**，點進去就能看到各家防毒引擎的判定結果。

### 防毒可能會擋

本工具未經程式碼簽章（[原因](#為什麼沒有數位簽章)），行為又包含列舉處理程序、讀取安全性事件記錄、查詢 Defender 設定 —— 這些和惡意程式的樣式有重疊，可能觸發警告。

**請不要因為想跑這個工具就關掉防毒。** 正確做法是先用上面的 SHA-256 與建置來源證明確認檔案無誤，再單獨放行這一個檔案。

### 需要什麼

- Windows 10 或 Windows 11（64 位元）
- 建議以**系統管理員身分**執行（差別很大，見下方說明）

不放心的話，**可以先用一般權限跑一次**看看它做什麼，再決定要不要給管理員權限 —— 見「[你不必相信我](#你不必相信我)」。

## 紫P 的官方資訊

以下是本工具用來判斷「你的紫P 是不是正版」的依據。**這些資料都是實際查證過的**，你也可以自己核對。

### 官方下載

| 項目 | 網址 |
|---|---|
| 官方下載頁 | `https://lineageclassic.plaync.com/zh-tw/download/index` |
| 安裝檔實際來源 | `https://gs-purple-inst.download.ncupdate.com/Purple/PURPLE_Installer_<版本>.exe` |

安裝檔檔名會隨版本改變（例如 `PURPLE_Installer_2_26_803_19.exe`）。

**認網域，不要認字串。** `plaync.com.evil.tw` 看起來有 `plaync.com`，但它真正的網域是 `evil.tw`。判斷方法是**從右邊往左讀**：最後兩段才是真正的網域。

### 官方網域清單

工具比對下載來源時使用的白名單：

```
plaync.com       遊戲官網
playnccdn.com    資源與圖片
ncsoft.com       公司官網
ncupdate.com     安裝檔與更新檔的下載主機
```

以及它們的子網域（例如 `gs-purple-inst.download.ncupdate.com` 是 `ncupdate.com` 的子網域，屬於官方）。

### 官方數位簽章

正版紫P 的簽章者資訊：

```
CN=NC Corporation, O=NC Corporation, L=Seongnam, S=Gyeonggi, C=KR
簽發者：Microsoft ID Verified CS EOC CA（Azure Trusted Signing）
```

**注意公司名稱是「NC Corporation」，不是「NCSOFT」** —— NCSOFT 已更名，舊資料上的 `NCSOFT Corporation` 已經不是現行的簽章者名稱。

你可以自己檢查手上的紫P：

```powershell
Get-AuthenticodeSignature "紫P安裝路徑\Purple.exe" | Format-List Status, SignerCertificate
```

- `Status` 應為 `Valid`
- 憑證的 `Subject` 應含 `O=NC Corporation`

> **憑證顯示「已過期」是正常的。** 官方使用 Azure Trusted Signing，憑證有效期只有短短幾天，簽章時會附上時間戳。只要 `Status` 是 `Valid` 就沒問題 —— 這代表簽章當下憑證有效。本工具的 M1-03 已正確處理這個情況。

### 執行前請先做兩件事

**1. 關閉天堂與紫P**

遊戲的反作弊機制會監控其他程式對它的存取。本工具刻意避開了所有會觸發它的行為，但關掉遊戲再跑最保險，也讓蒐證結果更乾淨。

關閉遊戲只會讓 1 個檢查項（M4-01）拿不到資料，而該項本來就不計分，**完全不影響風險評分**。

**2. 如果帳號真的被盜了，先回想一下時間**

工具會問你「最後一次確認正常」和「發現不見」大約是什麼時候，這個答案能讓報告直接把那段期間發生的事挑出來。不知道也沒關係，可以跳過。

**沒被盜、只是想檢查電腦的話，工具不會問這些。**

### 執行：直接雙擊就好

**用滑鼠連點兩下 `LcAudit.exe`。** 不需要打任何指令。

它會依序帶你走完：

1. **問你要不要用系統管理員身分執行** —— 建議選「是」，會跳出 Windows 的權限確認視窗。這個差別很大：

   | 執行方式 | 影響 |
   |---|---|
   | 關閉遊戲 | 少 1 項，**0 分**差異 |
   | **未以系統管理員執行** | **少約 8 項**，而帳號被盜當下的登入紀錄正好在那裡面 |

2. **問你這次檢查是因為什麼**，用方向鍵選：

   | 選項 | 接下來 |
   |---|---|
   | 我的帳號已經被盜了，想找出原因 | 再問兩個時間：最後一次確認正常是何時、什麼時候發現不見了（不知道可按 Enter 跳過） |
   | **沒有被盜，只是想檢查電腦目前的狀況** | **不會問時間**，直接開始檢查 |

   沒被盜也可以跑 —— 檢查項目完全一樣，只是少了「事發時間比對」那一段。

3. **開始檢查**，大約 10 秒

4. **問你要不要把報告上傳**給人幫忙看 —— 上傳前會列出報告裡有哪些資訊讓你確認

5. **停在畫面上等你按 Enter**，不會看完就關掉

報告會存在 `LcAudit.exe` 同一個資料夾底下的 `LcAudit-Report`。

### 進階：用指令列執行

如果你習慣用命令列，帶任何參數執行就會跳過上面的問答，直接照參數跑：

```powershell
LcAudit.exe --incident-time "2026-08-09 02:00" --incident-end "2026-08-09 07:30" --email
```

紫P 裝在非預設位置、工具找不到的話：

```powershell
LcAudit.exe --purple-path "D:\Games\PURPLE"
```

## 參數

| 參數 | 預設值 | 說明 |
|---|---|---|
| `--days <天數>` | `90` | 事件記錄回溯幾天 |
| `--purple-path <路徑>` | 自動探測 | 手動指定紫P 安裝目錄 |
| `--output <目錄>` | `.\LcAudit-Report` | 報告輸出位置 |
| `--format <格式>` | `All` | `Console` / `Json` / `Html` / `All` |
| `--skip-module <模組>` | 無 | 跳過指定模組，如 `--skip-module M3 M4` |
| `--incident-time <時間>` | 無 | **事發時間**（或區間起點），見下方說明 |
| `--incident-end <時間>` | 無 | 事發區間的結束時間（發現被盜的時間） |
| `--email` | 關閉 | 把報告打包成 zip 並開啟郵件草稿，見下方說明 |

### 強烈建議告訴工具事發時間

工具收集了大量時間點——遠端工具的安裝時間、紫P 的安裝時間、遠端登入紀錄、螢幕鎖定解鎖、帳號建立時間——但**沒有錨點的話，那些只是一堆要你自己比對的數字**。

**最好的講法是給一個範圍**，因為你通常知道的是「幾點還好、幾點發現不見」：

```powershell
LcAudit.exe --incident-time "2026-08-09 02:00" --incident-end "2026-08-09 07:30"
```

> 我 **02:00** 還在線上掛機，**07:30** 上線發現東西不見了 —— 事情就發生在這 5.5 小時內。

報告會在最前面列出所有跡證，**落在這個區間內的標成「★ 就在事發區間內」排最上面**。

只知道大概時間也可以：

```powershell
LcAudit.exe --incident-time "2026-08-09 04:00"
```

> 有一個真實案例：受害者電腦上的 AnyDesk，**安裝時間正好就是帳號被盜的時間**。這種關聯用肉眼在時間軸裡翻很容易漏掉，但只要給了錨點，它會直接出現在報告第一段。

**不必擔心時間抓不準。** 工具不會過濾掉「太久以前」的事件——它只是依距離排序，遠的會標明「事發前 30 天」讓你自己判斷。入侵的原因常常遠早於你發現的時間，攻擊者可能數週前就植入了工具，潛伏到適當時機才動手。

> 用 `--skip-module` 跳過模組時，分數仍以 100 分為基準計算，**跳過的項目一律計 0 分**。分數低不代表那些面向安全，只代表沒檢查 —— 報告會明確標註。

## 報告

執行後會在輸出目錄產生兩個檔案：

```
LcAudit-電腦名稱-20260810-143005-5f04e093fa62419fac2fd5660be07f5b.html   ← 給人看的
LcAudit-電腦名稱-20260810-143005-5f04e093fa62419fac2fd5660be07f5b.json   ← 給工具處理的
```

檔名最後那一長串是**報告識別碼**，每次執行都不同。它也印在報告內容裡，方便在多人求助時區分是誰的報告——不需要你附上任何個人資訊。

HTML 報告是**單一自包含檔案**，可以直接寄給別人或存檔，不需要網路也不依賴任何外部資源。內容分四段：

1. 風險等級卡片與「最可能的入侵途徑」推論
2. 時間軸 —— 所有帶時間點的跡證依時間排序
3. 各檢查項的完整明細（有問題的預設展開）
4. 取證保存提醒

## 需要作者協助分析時（選用）

> ### 這項功能預設關閉
>
> **報告已經存在你自己的電腦裡，不送出完全不影響檢查結果。** 你可以自己看、自己保存、或找任何你信任的人看。
>
> **只有在你看不懂報告、需要作者幫忙判讀時，才需要主動選擇送出。**

雙擊執行時工具會問你一次，**預設是「否」**——直接按 Enter 不會送出。用指令列的話：

```powershell
LcAudit.exe --email
```

送出前一定會先列出報告裡包含哪些你電腦上的資訊，並再次請你確認。送出成功後會顯示**報告識別碼**，把它告訴作者即可對照是哪一份。

### 送出的資料會被怎麼使用

**僅用於分析你這台電腦的資安弱點與可能的入侵途徑，不作其他用途。**

報告內含：

- 電腦名稱與 Windows 版本
- 本機使用者帳號名稱
- 曾遠端連入的來源 IP 位址與時間
- 已安裝的程式、服務與開機啟動項目的路徑
- 紫P 的安裝位置與簽章資訊

**不含**密碼、金鑰或遊戲帳號內容。

**送出前請自己看一眼。** 這仍是你電腦的完整輪廓——**如果這是公司電腦，請先確認公司規定。**

> 這是本工具唯一會連網的地方。不使用這項功能，就完全不會有任何網路連線。
>
> 上傳失敗（沒網路、防火牆擋住）不影響報告產生，工具會改為開啟郵件草稿讓你自行決定。

## 檢查項目

目前實作 **34 項**檢查，分四個模組。

### M1 — 紫P 完整性（9 項）

判斷你裝的紫P 是不是官方正版。**這是最關鍵的模組** —— 如果紫P 本身有問題，整台電腦就不能信任了。

| 編號 | 檢查什麼 | 嚴重度 |
|---|---|---|
| M1-00 | 找出紫P 裝在哪裡 | 資訊 |
| M1-01 | 主程式的數位簽章是否有效 | **極高** |
| M1-02 | 簽章者是不是 NCSOFT 官方 | **極高** |
| M1-03 | 憑證是否過期、有沒有時間戳 | 中 |
| M1-04 | 安裝檔是從哪個網站下載的 | **極高** |
| M1-05 | 安裝目錄裡有沒有未簽章的模組 | 高 |
| M1-06 | 有沒有檔名很像主程式的冒充檔 | 高 |
| M1-07 | 是不是裝在暫存或下載資料夾 | 高 |
| M1-08 | 安裝時間附近有沒有人遠端連進來 | 中 |

> **M1-06 抓的是這種**：`PurpIe.exe` —— 那不是小寫 L，是大寫 i。肉眼幾乎分辨不出來。
>
> **M1-04 抓的是這種**：從 `plaync.com.evil.tw` 下載的安裝檔。網址裡有 `plaync.com`，但真正的網域是 `evil.tw`。

### M2 — 遠端存取跡證（11 項）

還原「有沒有人連進來過、什麼時候、從哪裡」。

| 編號 | 檢查什麼 | 嚴重度 |
|---|---|---|
| M2-00 | 安全性記錄檔是否曾被清除 | 高 |
| M2-01 | 遠端桌面登入紀錄 | 高 |
| M2-02 | 來自公網的網路登入 | 高 |
| M2-03 | 密碼嘗試失敗爆量（暴力破解） | 中 |
| M2-04 | 終端服務工作階段時間軸 | 高 |
| M2-05 | 這台電腦連出去的 RDP 紀錄 | 資訊 |
| M2-06 | AnyDesk 連入紀錄 | 高 |
| M2-07 | TeamViewer 連入紀錄 | 高 |
| M2-08 | 其他遠端工具（共 10 種，清單見下） | 高 |
| M2-09 | RDP 畫面快取殘留 | 資訊 |
| M2-10 | 螢幕鎖定／解鎖時間軸 | 資訊 |

> **M2-00 為什麼重要**：清除事件記錄需要管理員權限，是入侵者湮滅跡證的典型動作。如果這項命中，M2 其他項目顯示「通過」就不具意義了 —— 證據可能已經被刪掉。
>
> **M2-10 怎麼用**：拿它跟其他時間軸對照。如果「螢幕鎖定期間」出現登入或安裝活動，那不會是你本人做的。

### M3 — 持久化與後門（10 項，尚有 3 項未實作）

檢查有沒有被留下長期潛伏的管道。

|---|---|---|
| M3-01 | 遠端桌面是否被打開 | 高 |
| M3-02 | 遠端桌面的通訊埠有沒有被改 | 高 |
| M3-03 | 誰可以遠端登入這台電腦 | 高 |
| M3-04 | 有沒有多出來的帳號 | 高 |
| M3-05 | 系統管理員群組有沒有多出成員 | **極高** |
| M3-06 | 開機自動啟動的項目 | 高 |
| M3-08 | 自動啟動的服務 | 中 |
| M3-10 | Defender 的排除清單 | 高 |
| M3-11 | Defender 即時防護是否被關閉 | 高 |
| M3-13 | hosts 檔有沒有被改去別的地方 | **極高** |

**尚未實作**：M3-07（排程工作）、M3-09（防火牆規則）、M3-12（WMI 事件訂閱）。

> **M3-13 為什麼是最高等級**：hosts 檔被改之後，你輸入官網網址、網址列顯示的也是官網，但實際連到的是攻擊者的主機。這是最難察覺的釣魚方式。

## 怎麼看結果

### 風險等級

| 等級 | 分數 | 結束代碼 |
|---|---|---|
| 低 | 0–19 | 0 |
| 中 | 20–49 | 1 |
| 高 | 50–79 | 2 |
| **極高** | 80–100 | 3 |

**只要有任何一項「極高」等級的檢查判定為異常，整體就直接是「極高」**，不管總分多少。這類項目命中代表端點已經不可信，分數多寡沒有意義。

（結束代碼 `10` 代表執行環境錯誤。）

### 每一項的四種結果

| 結果 | 意思 |
|---|---|
| **通過** | 這項沒發現問題 |
| **警告** | 有可疑跡象，需要你自己判斷 |
| **異常** | 明確有問題 |
| **無法判定** | 因為權限不足、路徑不存在等原因**沒檢查成**。**這不等於安全** |

「無法判定」和「通過」是完全不同的兩件事，報告會分開呈現。

### 三件必須知道的事

1. **全部通過不代表沒被入侵。** 取得管理員權限的攻擊者可以清除事件記錄；rootkit 等級的隱藏無法用一般方式偵測。
2. **如果 M1 有命中，其他結果都不必看了** —— 端點已經不可信，建議直接重灌。
3. **帳號被盜未必是電腦的問題。** 如果全部通過，被盜途徑更可能在帳號側：釣魚網頁、信箱被打穿、或 OTP 被社交工程騙走。工具會在推論結論裡指出這一點。

## 如果發現異常

**先保存證據，再處理。**

1. 完整保存 HTML 與 JSON 報告到**另一台電腦或隨身碟**
2. 匯出原始事件記錄（需系統管理員）：
   ```powershell
   wevtutil epl Security .\Security-backup.evtx
   wevtutil epl "Microsoft-Windows-TerminalServices-LocalSessionManager/Operational" .\TS-backup.evtx
   ```
3. **在另一台乾淨的裝置上**更改遊戲帳號與信箱密碼 —— 在可能被入侵的電腦上改密碼等於直接送給對方
4. 報案時準備：時間點、來源 IP、遊戲內損失清單、官方 1:1 客服單號

## 為什麼可以放心執行

**不會被反作弊當成外掛。** 這個工具的所有行為都是唯讀查詢，且刻意避開了所有會觸發反作弊的操作：

- 不讀取任何其他程式的記憶體
- 不對遊戲程序開啟高權限控制代碼（取程式路徑時只用最小權限）
- 不啟用偵錯權限、不注入、不掛鉤、不載入驅動
- 偵測到遊戲執行中時，會自動跳過需要碰觸遊戲程序的檢查

**不會動到你的系統。** 除了 `--output` 指定的報告目錄之外，不寫入任何位置，也不修改檔案時間戳。

## 自行建置

不信任別人編的執行檔是合理的 —— 你可以自己編。

```powershell
git clone https://github.com/TimothySu2015/LcAudit.git
cd LcAudit

dotnet build
dotnet test

# 直接執行
dotnet run --project src/LcAudit.Cli -- --days 90

# 發佈成單一自包含執行檔（輸出在 .\publish）
dotnet publish src/LcAudit.Cli -c Release -o publish
```

需要 [.NET 10 SDK](https://dotnet.microsoft.com/download)。發佈設定已寫在專案檔中，不必額外指定參數。

Release 頁面上的執行檔是由 GitHub Actions 用同一份設定自動建置的（見 `.github/workflows/release.yml`），沒有經過任何人的電腦。

## 已知限制

| 限制 | 說明 |
|---|---|
| 事件記錄可被清除 | 有管理員權限的攻擊者可以刪掉紀錄。M2-00 會偵測這件事 |
| 事件記錄有保留上限 | 超過保留期的紀錄無法還原，回溯天數再長也查不到 |
| 無法偵測 rootkit | 使用者模式的 API 看不到核心層級的隱藏 |
| 看不到廠商端 | 帳號在遊戲公司那邊是否被異動，只能靠官方的登入紀錄 |
| 白名單需要維護 | 官方網域與遠端工具清單是內建的靜態資料，官方變更時需要更新 |
